summary: Everything a page means is in its IR, and any host can draw it: a public drawn tree, text as calls, IR 4 and faster builds.

Run `xtmd migrate` on your documents and packs: it makes every change to the language below that has one answer, and leaves the rest with a TODO and the reason. `xtmd migrate page.ir.json` brings a built IR to IR 4, or build it again.

## New
- **A host of your own.** A page is now a public tree to draw: plain JSON with its own schema (`schemas/tree.schema.json`), an id for each widget that follows its item, the events and writes that do something, and a failed widget in its own place. After each change you are told only what changed. `page.event(id, …)`, `page.write(id, …)` and `page.call(id, …)` are the way in. Our own packages use this and nothing else. Read [Writing a host](https://github.com/extended-mark/extended-mark/blob/main/docs/guides/host.md); `apps/example-host` is a whole one, drawn on a server and taken over in the browser.
- **Your own components as widgets**, in React, Vue, Svelte, Solid and Angular: `components={{ "acme/chart": Chart }}` on `XtmdDoc`, each given the widget's node, `event`, `write`, `call` and its slots.
- **`xtmd build docs --out dist --engine web`** builds documents into files with an engine that is a program: every document's IR on its standard input, the files it makes on its standard output (`schemas/build.schema.json`). Engines are named in `xtmd.toml`'s `[engines]`.
- **`xtmd build` and `xtmd md` take many files.** `xtmd build docs --out dist` builds a folder, each document at its place, with core compiled once and the packs of its own `xtmd.toml`. With `--format json` it says what became of each.
- **`xtmd migrate` takes IR files**, one way, checked against the schemas of both versions. It keeps the page's Markdown or says what is missing.
- **`warn`** beside `require`: a rule that tells the host when it is false and stops nothing.
- **An extern widget's whole contract is in its declaration**: `tokens`, `uses`, `require` and `warn`, and `markdown #quote;` when it is one of Markdown's own pieces, for any pack as for core. An `extern` block may have `tokens` too.
- **`docs/guides`**: writing a host, and writing an engine. `examples/pack-migration` is a pack going from one version to the next, with its documents.
- **The web engine,** `@extended-mark/web`: `xtmd build docs --out dist --engine web` writes pages ahead as HTML, CSS and scripts, with no runtime and no IR in them. A page is whole before its script runs, and one that never changes has none.
- **`xtmd build --pretty`** writes the IR over several lines.

## Changed
- **Breaking, the words.** What shows a page is a *host* (it was "app"), and what runs its IR is an *engine* (it was "target"; "run time" and "real time" are *static* and *live*). In the spec `app` is `host` and `targets/` is `engines/`; `needs.app` in the IR is `needs.host`.
- **Breaking, a slot is an input.** A call fills every slot that isn't `opt`, in code and in prose alike, and a plain block fills a widget that has one slot. `frame` in prose needs `@body { … }`, as it has two. Migrated: a left-out slot becomes an empty one, or a TODO where that isn't certain.
- **Breaking, `md` is `rich_text`.** `rich_text` is one built-in type for all Markdown in a value, a sentence or blocks, and it is a view: place it with `\{x}` or `@x;`. `md`, `block`, `segment`, `part`, `marks`, `list_item` and the widget `blocks` are gone. A `\{x}` hole given a `rich_text` places it. Migrated; code that takes a `rich_text` apart or compares one is left with a TODO.
- **Breaking, a sentence is calls.** Words and marks are extern widgets (`core/words`, `bold`, `italic`, `strike`, `link`, `code_span`, `inline_math`, `inline_image`, `note_mark`, `line_break`), like everything else a page draws, and any widget may stand among them. An engine's or a host's drawing of sentences has to draw these.
- **Breaking, an extern widget says its Markdown.** One that said nothing is `markdown { }`. Migrated.
- **Breaking, a `let` at the top of a file is a constant.** One that reads `$state` or the host, or calls an `extern fn`, is a compile error that says so: write a fn, `fn total(): number { return …; }`, and read it as `total()`. A `let` inside a widget, a view or a fn is as it was.
- **Breaking, one widget set for the web,** `@extended-mark/widgets`. A host's widget for `@extended-mark/dom` and `@extended-mark/embed` is a fn of plain elements, as the frameworks' are, or an element of its own given in `own`. `Mounted.view(id)` is `element(id)`, and the stylesheet is `@extended-mark/widgets/style.css`.
- **Breaking, the host brings the IR.** `src` is gone from `XtmdDoc` on the web, in every framework: fetch the IR and give it as `ir`. Until it has one, the document shows that it waits. `@extended-mark/embed/html` is `@extended-mark/view/html`.
- **Breaking, `warn` is a keyword.** A name spelled so is `warn_`. Migrated; a host that reads or sets it reads the new name.
- **Breaking, `provides`, `uses`, `migration` and `execute` are keywords,** so no name can be one.
- **Breaking, a record's field is written only when it is `mut`,** as page 1 has always said: an assignment, a `mut` argument or input, `if (mut …)` and `mut for` on any other field is a compile error that names it. Write `mut` before the field, or change the record with `with`.
- **Breaking, IR 4.** The IR is compact, has its own whole-number version apart from xtmd's, and holds only what the page can run: no bindings or reads, no cases, tokens or fns the page can't reach, and Markdown only where it isn't the view. `needs` lists every value taken from others, the host's included (`core/page.width`). An engine reads one IR version and refuses another by name.
- **Breaking, `@extended-mark/runtime`'s API.** `Page` is the host's side: `tree()` (JSON nodes), `node(id)`, `onChange(changes)`, `event/write/call` by id, `data()` and `restore()` for what a page holds, which `new Page(ir, { data })` starts from. `observeTree`, `observeState`, paths and `Value` classes are no longer public. A widget in `@extended-mark/dom`, or one given to `XtmdDoc`, is drawn from a node: its inputs in the IR's form, a slot among them. The exported type `Value` is `Input`.
- **Breaking, `$state` given to a page is checked** as a host's write is: what doesn't fit is refused, told, and keeps its starting value. In Rust too (`PageOptions.state`).
- **Breaking, `xtmd target check` is gone**, with its protocol, cases and adapters. Whoever writes an engine checks it.
- **Breaking, `core.gfx`:** an extern says `uses core.gfx`; that a spot is outside its plane is the plane's `warn`, told once; and the checker has no rule of its own left for chained `sizing` or for `shade` by its name. A fn with a return type given to any extern widget warns that it may run often, as it did for `shade`.
- **Compiling is about ten times faster.** A small page compiles in about 12 ms where it took 130, and starting the compiler takes half as long. A long page gains more: 200 paragraphs compile in about 20 ms where they took 500, as the compiler reads a sentence's Markdown itself.
- **A page works out only what reads a change**, down to an item of a list: a click in one of 300 rows takes 4 ms on the web where 0.3.2 took 10. It is drawn once when it is made, whatever `$state` or snapshot it is given. An IR is told apart by its content: the same page given again goes on.
- **Themes.** `@extended-mark/dom` writes both themes' values in one stylesheet under `data-xtmd-theme`, so a theme changes with an attribute and one server drawing serves both.
- **A shade is painted again** only when its shader reads something that changed.
- **The Markdown writer** writes a mark once around all the words that share it, with spaces outside it.

## Fixed
- A page whose widget held a fn in a variable couldn't be put back from its own data: the variable is left out, as what doesn't fit is.
- An item a handler added to a list could be taken for another that was there: it was drawn as that one, and a write to it changed that one. And a list the host replaced kept its rows' own variables, by place. Every item of a page is now its own (page 3).
- A field kept what a person was composing (an IME) only until the page drew it again: React, Vue and Angular put the old text back.
- An `extern fn`'s default was taken for its value as a file was compiled, in a `let`, a default, a bound and a proof, whoever supplied it.
- `@name` draws the widget a `let` at the top of a file holds: it was an unknown widget.
- A `@@@` line inside a fenced code block no longer ends the definitions.
- A slot whose content changed while the page ran could show what it held before, and a widget in a list slot wrote its Markdown with starting values.
- A block given to a value after `@` was lost, and a slot of one widget took any number: both are compile errors.
- `@icon` in a sentence could be hidden by an input of the same name.
- `xtmd migrate` refuses a result that doesn't compile even when only a release's own step moved it.
- A value written into a record's field through a `mut` input or parameter is checked against the field's contract, and one written back to a `mut` local against the local's.
- A record's `require` is checked again when one of its fields is written.
- Everything that comes to a page from outside is checked whole, its type and every contract in it: what a widget writes, the arguments of events and exposed fns, extern values, what an engine's fn gives, and records, cases and lists a host writes. One that doesn't fit is refused and told.
- A failure in a document's own sentence, branch or loop is a notice in its place: it stopped the whole page, and came out of `new Page` and `page.set` as an exception.
- `--out=file` and `--config=file` are read, as `--pack=` was.
