INDEX: WHERE EVERYTHING LIVES
Each file here lists one area, with a line on what each place does. Paths are from the repository's
root. Why things are as they are is in .knowledge/, what the language means in docs/specs.

  01-compiler.txt         compiler/: the one crate xtmd (its parts), wasm, npm
  02-core.txt             core/: the standard library, a pack
  03-schemas.txt          schemas/: the JSON between modules, and the types generated from it
  04-runtime.txt          engines/published/runtime: runs a page, in TypeScript
  05-web-drawing.txt      engines/published/widgets and dom: draw a page on the web
  06-web-bindings.txt     engines/published/bindings: React, Vue, Svelte, Solid, Angular, Next, plain
  07-rust-engines.txt     engines/examples/rust: the native runtime, egui
  08-android.txt          engines/examples/misc/android: the native runtime in Kotlin, Compose
  09-editors.txt          ide/: language server, VS Code extension
  10-apps-examples.txt    apps/, examples/, brand/, devbench/
  11-checks-tests.txt     checks/ and every test suite
  12-docs-notes.txt       docs/specs, docs/guides, notes/
  13-release-ci.txt       tools/, .github/, install scripts, VERSION
  14-web-engine.txt       engines/published/web: pages built ahead
  20-TASKS.txt            "I want to change X": the places to touch, in order

THE TREE
  compiler/               the one compiler, in Rust (xtmd/); its cargo workspace holds every crate
  core/                   core, written in Extended Mark (.xtmdpack)
  schemas/                JSON Schemas: ir, rir, tree, check; earlier IRs in schemas/ir-history
  engines/published/      on npm: runtime, widgets, dom, web, bindings/*
  engines/examples/       never published: rust (runtime, egui, egui-live), misc/android
  ide/                    vscode (an extension); README.md, the language server for any editor
  apps/                   playground, example-host
  examples/               small hosts and packs that use what is published
  checks/                 compiler cases, the rule table, CommonMark, shared pages
  docs/                   specs (the language), guides (host, engine)
  notes/                  release notes, a file a version
  tools/                  release, llm (checks these notes), cli-usability
  brand/                  logo and icons
  devbench/               video takes, recorded for demos
  .github/                workflows, rulesets
  VERSION                 the release's version; tools/release/bump.mjs raises it everywhere
  README.md, CLAUDE.md    for people, for agents
  install.sh, install.ps1 one-line installers of the xtmd binary

THE SHORTEST WAY THROUGH THE CODE
  text -> compiler/xtmd/src: syntax (tree) -> check (IR, whole) -> lower (IR, only what runs)
       -> a runtime (drawn tree, changes) -> what draws (elements) -> the reader's events back
